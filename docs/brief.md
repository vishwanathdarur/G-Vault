# Q-Vault: Architectural Brief

This document provides a brief, high-level explanation of the Q-Vault compiler pipeline. It breaks down exactly what happens at each stage when a user runs a query like `SELECT name WHERE age > 20`.

## 1. JSON Parser (The Baseline)
**What it does:** Reads raw JSON text (`{"name": "Alice", "age": 25}`) and converts it into a structured C++ tree in memory (an Abstract Syntax Tree, or AST).
**Why:** Computers can't easily search raw text. Converting it to a tree allows us to navigate the data programmatically.

## 2. Query Lexer
**What it does:** Takes the user's query string and chops it up into meaningful "Tokens".
**Example:** `WHERE age > 20` becomes `[KEYWORD_WHERE] [IDENTIFIER:"age"] [OPERATOR_GT] [NUMBER:20]`.

## 3. Query Parser
**What it does:** Takes the flat list of Tokens from the Lexer and organizes them into a logical tree (Query AST) using grammar rules.
**Why:** It ensures the query makes grammatical sense (e.g., catching errors like `WHERE > age 20`).

## 4. Semantic Analysis
**What it does:** Traverses the Query AST to perform type-checking.
**Why:** If the user writes `WHERE age > "twenty"`, this stage throws an error because you cannot compare an integer to a string. It guarantees the query is safe to execute.

## 5. IR Generation & Optimization (The Middle-End)
**What it does:** Converts the Query AST into an Intermediate Representation (IR) and optimizes it for speed.
* **Constant Folding:** Simplifies static math (e.g., `age > 10 + 10` becomes `age > 20`).
* **Predicate Reordering:** Moves fast checks before slow checks (e.g., checking an integer before performing a heavy string comparison).

## 6. Bytecode Generation
**What it does:** Translates the optimized IR into low-level instruction codes (Bytecode). 
**Example:** `LOAD_FIELD "age"`, `PUSH_CONST 20`, `CMP_GREATER_THAN`.
**Why:** Executing bytecode is significantly faster than constantly traversing a complex AST during runtime.

## 7. The Virtual Machine (VM)
**What it does:** A custom, stack-based runtime environment that executes the generated Bytecode against the JSON AST.
**Why:** The VM loops through the JSON records, runs the lightning-fast bytecode instructions, and extracts only the records that evaluate to `true`.

## 8. Projection Pruning (Memory Optimization)
**What it does:** Analyzes the `SELECT` clause before touching the JSON file. If the query only asks for `name`, the system lazily streams the file and ignores all other fields (like `address` or `emails`).
**Why:** Prevents Q-Vault from crashing on massive, gigabyte-sized log files by ensuring we never load unnecessary data into RAM.
